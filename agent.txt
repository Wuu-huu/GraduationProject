项目名称：类哔哩哔哩视频平台

全局规则：
1. 先规划，后编码。复杂任务必须先输出目录结构、设计说明、文件变更计划，再开始写代码。
2. 当前阶段后端采用 Spring Boot 多模块架构，不使用 Spring Cloud 微服务，但代码边界要为未来升级 Spring Cloud 做准备。
3. 当前阶段推荐功能只实现“数据驱动 + 协同过滤”，优先 ItemCF，不实现 Elasticsearch，不实现复杂深度学习推荐。
4. 必须严格基于现有数据库设计开发，不得擅自推翻数据模型。
5. 所有代码必须可运行、可编译、可联调，不接受纯空壳或仅示意代码。
6. 所有接口必须统一返回格式，所有状态字段优先使用枚举，避免魔法数字。
7. 所有写接口必须做权限校验和资源归属校验。
8. 每阶段完成后必须说明：
   - 新增/修改了哪些文件
   - 如何运行
   - 如何验证
   - 有哪些待确认问题
9. 前端必须组件化、工程化，不要只生成静态页面。
10. 如发现需求冲突，先列出问题和建议，再暂停等待确认。
11. 后续新增或修改 Java 代码时，必须补充简洁且有效的注释，重点说明类职责、关键方法、复杂业务判断、安全校验点和扩展边界，避免无意义注释。
12. 在需要排查问题、记录上下文或访问关键链路的代码中，优先使用 try-catch 并输出清晰日志，尤其是 controller、service、数据库访问前后和外部组件调用处；禁止空 catch 或吞异常。
